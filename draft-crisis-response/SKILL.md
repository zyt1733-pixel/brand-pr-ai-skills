# 舆情危机回应口径

## 核心目标

把回应写成可被公众检验的处置记录，而不是情绪化辩解或价值观口号。先处理利益相关方的损失与担忧，再说明事实、责任、动作和下一次更新。

## 加载参考资料

- 每次起草前读取 [response-framework.md](references/response-framework.md)，完成事实、责任、场景和阶段判断。
- 需要生成具体文本时读取 [template-library.md](references/template-library.md)，按场景选骨架，不直接照抄。
- 定稿或审核现有声明时读取 [quality-gates.md](references/quality-gates.md)，逐项过闸。

## 工作流

### 1. 建立最小事实包

先整理以下信息；信息不足时保留明确占位符，不自行补全：

1. 已确认发生了什么、何时发生、涉及谁、影响范围多大。
2. 哪些仅为指控、推测或内部初步判断。
3. 当前止损、调查、补救、整改动作及负责人。
4. 是否已有监管、司法、专业机构或第三方介入。
5. 哪些数据、结论和承诺可公开，哪些暂不能公开。
6. 下次可更新时间与公众联系入口。

把信息分成“可说事实”“待核信息”“禁止表述”三栏。没有证据时，不写“已查明”“绝无”“均符合”“行业平均”等结论。

### 2. 判断责任层级与回应阶段

区分直接责任、管理责任、合同责任、平台治理责任和协助责任。即使直接责任尚未确认，也可以先对已造成的困扰、担忧或损失表达关切，并说明正在采取的动作。

选择回应阶段：

- 事实未清但关注度高：先发首次简短回应，确认关注、启动核查、先行止损、承诺更新。
- 关键事实已清：发布详细回应，说明范围、原因、责任、补救和整改。
- 错误信息扩散：先承认真实部分，再用可验证证据纠正错误部分。
- 监管已介入：以配合调查和落实要求为主，不抢先替监管下结论。

高风险事件优先采用“两阶段回应”：第一次争取时间和信任，第二次交付事实与行动。不要用一篇未经核验的长声明同时完成所有任务。

### 3. 制作回应地图

对每个核心质疑分别写出：

- 公众真正担心什么。
- 当前能确认什么。
- 用什么证据支持。
- 企业承担什么责任。
- 已经采取什么动作。
- 谁受益、如何补救。
- 哪一点暂不能确认，何时更新。

一条质疑对应一条证据链和一组动作。不要把多个问题塞进“持续优化”“加强管理”一句话。

### 4. 按五段结构起草

1. **确认事项**：准确复述所回应的问题，避免模糊指代。
2. **回应影响**：承认给相关方造成的实际影响；责任确认时正式道歉，责任未明时对影响致歉并保留调查结论。
3. **说明事实**：只写已核验时间、范围、过程和证据，明确已知与未知。
4. **交付行动**：写清止损、调查、补救、整改、复盘五类动作中的相关项，尽量包含对象、负责人、时限和验证方式。
5. **承诺更新**：给出下一次更新时间、服务入口或后续公开方式，并欢迎监督。

先写事实和动作，再补态度。每个抽象承诺后至少跟一个具体动作。

### 5. 生成媒体问答

为最尖锐的五到十个问题准备答复。每个答案使用“结论—事实—行动—边界”结构：先正面回答，再给依据，再说处置，最后说明待核内容或下一次更新。不要重复问题中的攻击性标签，也不要用“无可奉告”结束可合理回应的问题。

### 6. 执行发布前审核

使用 [quality-gates.md](references/quality-gates.md) 检查：事实来源、受影响者视角、责任一致性、动作可执行性、承诺时限、法律风险、隐私保护、语气和二次传播风险。任何关键事实无法支撑、补救措施尚未获批或责任口径内部冲突时，明确标记“暂不可发布”。

## 默认交付格式

按以下顺序输出：

1. **回应策略**：风险判断、目标受众、回应阶段、责任边界。
2. **事实缺口**：发布前必须补齐的问题。
3. **对外回应正文**：可直接审阅的文本。
4. **媒体问答**：尖锐问题与简洁答复。
5. **发布前检查**：仍需法务、业务、客服或管理层确认的事项。

如果用户只要一句短口径，仍先在内部完成判断，但仅交付所需长度。

## 不可突破的边界

- 不捏造调查结果、数据、第三方证言、监管意见或用户反馈。
- 不把“正在核实”包装成事实澄清，不以“个别情况”淡化未核实的系统性问题。
- 不用删帖、压制投诉、诱导撤诉、虚构支持或制造舆论对冲作为解决方案。
- 不公开受影响者的个人信息，不把内部敏感信息写入对外口径。
- 不承诺未获授权的赔付、时间、处罚或制度变更。
- 不以合作方、门店、员工或技术故障作为简单甩责对象；说明治理责任与具体措施。
- 可复用版本默认去除企业名、产品名、人名、城市名和内部代号，改用角色占位符。
