# 发布前质量闸门

## 一票否决项

出现任一项即标记“暂不可发布”：

- 关键结论没有可追溯来源。
- 把待核信息写成既定事实。
- 赔付、处罚、时限或制度变更尚未获授权。
- 声明与客服、业务、法务或监管报送事实冲突。
- 泄露受影响者隐私、商业秘密或调查敏感信息。
- 使用压制投诉、购买沉默、虚构第三方支持或制造假声量等方案。
- 对人身、财产、隐私等严重影响使用明显弱化词。

## 八项评分

每项按 0、1、2 分评分；低于 14 分继续修改。

1. **事项清晰**：读者能否立即知道回应什么。
2. **事实可靠**：时间、范围、数字和来源是否可核查。
3. **受影响者优先**：是否先回应损失、担忧与补救。
4. **责任一致**：责任表达是否与证据及法律判断一致。
5. **动作具体**：是否写清对象、动作、负责人、时限或验证方式。
6. **未知透明**：是否明确待核事项与下一次更新。
7. **语言克制**：是否避免攻击、煽情、绝对化和空话。
8. **全渠道一致**：声明、问答、客服与内部通知是否同源。

## 高风险表达替换

| 高风险表达 | 问题 | 改写方向 |
| --- | --- | --- |
| “高度重视” | 只有态度，没有交付 | 后接已完成动作、负责人和时限 |
| “个别现象” | 可能过早缩小范围 | 写“截至【时间】已核查【范围】” |
| “完全符合规定” | 结论过满 | 指明规定、适用范围和验证材料 |
| “绝不姑息／零容忍” | 易成为空口号 | 写暂停、复核、处罚和追踪机制 |
| “技术原因” | 模糊责任 | 写具体系统、影响范围和修复动作 |
| “给您带来不便” | 可能弱化严重损失 | 按实际影响写困扰、损失、伤害或隐私风险 |
| “请大家相信” | 要求信任但不给证据 | 提供记录、数据、第三方验证或更新时间 |
| “与我们无关” | 易被理解为甩责 | 说明直接责任、治理责任和协助措施 |
| “行业惯例” | 不能证明合理或合法 | 给出具体依据，并单独回应用户权益 |

## 句子级检查

- 每段只承担一个功能：确认、致歉、事实、行动或更新。
- 结论放在前，背景放在后。
- 删除不能带来新事实、新动作或新边界的口号。
- 将“加强、完善、优化”改成可观察动作。
- 避免连续使用被动语态，让责任主体清晰。
- 所有占位符必须替换；无法替换的内容改写为“仍在核查”。

## 去标识化检查

制作可复用 Skill、模板或培训材料时：

- 删除企业名、产品名、人名、门店名、城市名、内部代号和可反向识别的独特数据。
- 使用【企业】【业务线】【产品】【合作方】【受影响者】【有关部门】等角色占位符。
- 保留结构、判断和动作逻辑，不保留可识别案例细节。
