# 智猫舆情危机风险评估

## 目标

把零散、矛盾或不完整的危机信息，转化为一份可供企业管理者、公关负责人、法务和业务部门共同决策的风险评估。

本 Skill 只做风险研判与优先处置方向，不替代事实调查、法律意见、监管判断和企业最终决策。

## 使用前必须读取

每次执行前，完整读取：

1. `references/eight-dimension-model.md`：八维判断规则、定级方法和升级条件。
2. `references/report-format-and-guardrails.md`：报告格式、信息来源规则、质量检查和安全边界。

若用户提供了企业内部材料、舆情数据、评论样本、案例文件或网页链接，先读取材料，再开始评估。

## 总体流程

严格按以下顺序执行，不跳步：

```text
信息采集与来源标注
→ 事实确认卡
→ 八个维度依次分析
→ 四个关键维度综合定级
→ 升级条件校验
→ 形成决策型风险报告
→ 运行质量与安全检查
```

## 第一步：建立事实确认卡

从用户材料中提取：

- 什么时候发生；
- 在哪里发生；
- 涉及哪些主体；
- 发生了什么；
- 已知原因是什么；
- 谁最先公开发声；
- 企业可能承担什么责任；
- 当前传播平台、热度、媒体和意见领袖情况；
- 公众主要在讨论什么；
- 过去三年是否有同类危机；
- 已采取哪些措施；
- 哪些信息仍未确认。

给每条关键信息标注来源：

- **企业已确认**：来自企业内部核实材料；
- **用户提供**：来自当前用户陈述；
- **公开来源**：来自可访问、可引用的公开材料；
- **分析推断**：根据已知事实作出的有限推断；
- **待确认**：当前没有可靠依据。

不要用推断填补事实空白。不同来源冲突时并列呈现，不擅自选择一方覆盖另一方。

## 第二步：决定是否需要补充检索

出现以下情况且具备联网能力时，补充检索：

- 用户明确要求检索或核实；
- 事件正在传播，需要确认当前热度；
- 用户提到媒体报道、监管通报或公开声明，但未提供原文；
- 缺少事件时间、公开回应或传播范围。

优先使用企业声明、监管文件、平台原帖和权威媒体等一手来源。引用公开信息时提供链接或清楚的来源名称。

如果没有联网、没有检索或没有找到可靠来源，明确写出，不得使用“据公开报道”等暗示已经核实的表达。

## 第三步：依次完成八维分析

始终按固定顺序分析：

1. **事实还原**：还原5W，标出矛盾、缺口和更新时间。
2. **事件源头与动机**：判断触发者身份、可能动机、核心诉求和应对对象。
3. **企业责任**：判断企业责任程度、是否存在同类历史、责任是否需要升档。
4. **危机类型**：归入战略选择、业务执行、内部治理、外部关联、外部侵害与误解之一；信息不足时进入复杂兜底类。
5. **事件范围**：判断问题存在于集团、业务线、多区域、单店还是单点。
6. **传播态势**：判断传播当量、传播阶段和主战场。
7. **公众心理**：识别一至两个主导情绪、情绪解除条件、回应方向和禁忌。
8. **衍生风险**：评估监管、财务、经营、法律风险和七类受影响人群。

八维分析不是八段互不关联的评论。每个后续维度必须继承前面已经确认的事实和判断。

## 第四步：综合定级

先分别得到以下四项内部色级：

- 企业责任色级；
- 事件范围色级；
- 传播态势色级；
- 衍生风险最高色级。

综合定级取四项中最严重的一档：

```text
综合定级 = MAX（责任、范围、传播、衍生风险）
```

同时执行以下规则：

- 传播态势达到红色，综合等级直接为红色；
- 出现死亡、重伤或群体入院，综合等级直接为红色；
- 涉及敏感群体、三层共振或企业忽视明确的同行或海外预警时，在原等级上升一档，最高为红色；
- 特殊敏感时期只增加谨慎提示，不自动改变色级；
- 过去三年同类危机出现一次，责任程度升一档；出现两次以上，责任程度升两档，最高到企业全责档。

必须分别展示：

- **综合风险等级**：整体需要投入多大响应资源；
- **企业责任程度**：企业究竟该承担多少责任；
- **传播紧迫度**：多快需要更新信息；

不得把“红色”直接解释成“企业全责”。事件也可能因为传播极强或衍生风险极大而被定为红色。

## 第五步：信息不足时继续评估，但必须降级表达

不要用连续追问阻塞用户。信息不完整时：

1. 先输出“初步评估”；
2. 对缺失维度标注“待确认”；
3. 给出条件分支，例如“若确认存在系统性产品缺陷，等级将由橙色升为红色”；
4. 列出最需要补充的三至五项信息；
5. 降低结论确定性，不把推测写成事实。

以下三类关键事实同时缺失时，不给唯一色级，只给区间：

- 企业责任基本事实；
- 当前传播数据；
- 是否存在人员伤亡或重大现实损失。

## 第六步：输出报告

按 `references/report-format-and-guardrails.md` 的固定模板输出。

报告必须结论先行，并至少包含：

- 当前综合等级；
- 企业责任判断；
- 传播紧迫度；
- 三个最关键风险；
- 八维分析表；
- 定级计算过程；
- 可能升级的条件；
- 未来数小时内的优先方向；
- 信息缺口与重新评估条件；
- 时间快照和适用边界。

如果用户只问“这件事严重吗”，先给一页式简报，再询问是否需要完整报告；如果用户明确要求完整评估，直接输出完整版。

## 第七步：运行质量检查

交付前逐项检查：

- 是否把用户陈述误写成已核实事实；
- 是否给每个数字、日期和人名提供依据；
- 是否完整覆盖八个维度；
- 是否把责任、范围、传播和衍生风险分开；
- 是否解释综合等级为何形成；
- 是否写明关键信息缺口和升级条件；
- 是否避免法律定性、赔偿金额和无法承诺的期限；
- 是否避免暴露内部场景编号、动作编号、案例编号和媒体分级；
- 是否避免把正常批评预设为恶意攻击；
- 是否在伤亡事件中把人的安全、照护和尊严放在最前；
- 是否使用克制、清晰、可执行的语言；
- 是否明确该报告是特定时间点的决策辅助快照。

## 与其他任务的衔接

风险评估完成后：

- 用户需要策略时，把本报告作为危机策略 Skill 的输入；
- 用户需要声明时，先把已确认事实、责任程度、主导情绪和出面层级传给声明 Skill；
- 用户需要复盘时，把本报告的初始判断与最终事实对照，记录判断偏差；
- 用户需要企业系统接入时，优先输出结构化 `assessment_card`，但只有用户明确要求机器可读格式时才输出。
